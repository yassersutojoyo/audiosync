# Clauses of docs/CAST_SPEC.md that a later stage of the sender implements,
# so no test covers them yet. One per line: the clause ID, a space, the reason.
# tests/spec_coverage.rs fails if a clause listed here gains a `// covers:`
# test, so this list only shrinks. "Partly done" names what already exists.

# Connection.
C20 TLS 1.2 with ECDHE-RSA AES-GCM and CBC suites: the platform TLS stacks offer them, but native-tls can't pin a server suite in a test; G4 records what devices accept (partly done: TLS 1.2 minimum, a TLS 1.2-only server connects, handshake errors carry the TLS stack's reason).

# Groups.
C103 One stream response per source address for a group, at most one per member plus one: the stream server still serves one response at a time (partly done: the stream server answers the group's current addresses and those of the discovered devices that match a member, as the host updates them; a new GET still replaces the open response from any address, C61).

# Timing: hardware, and the app's interface.
C74 Latency of seconds: hardware, G7.
C75 Growing latency: hardware, G7 (partly done: drops and rebuffers are counted, C79).
C77 Measured-offset output: the Mac app's per-speaker delay control and its wording, M5 (partly done: OUTPUT_SYNC says measured offset, DeviceMemory stores the offset per device id and changes it only on the host's request, and the Windows app sets it from the speaker's delay control, says it is set by ear and keeps it between runs; with AirPlay on as well, the Windows app holds the AirPlay speakers, up to the sender's 3000 ms delay (P99), or the Cast feed back so both play at the longer of L and the offset).
