This one is mostly about what's under the Mac app's hood, plus a first look at AudioSync on Windows.

## On the Mac

AudioSync now plays your audio through a new engine written in Rust. You shouldn't hear a difference, and that's the point: it's the same capture, delays, equalizer and AirPlay as before, on a base that the Windows version shares. If something sounds off, the old Swift engine is still there. Hold Option while you open the AudioSync menu and choose "Use Swift Audio Engine (Next Start)"; it takes over the next time streaming starts, and the choice sticks until you pick the item again.

Other things you'll notice:

- TVs and other AirPlay speakers with a screen show what's playing in Spotify or Music: title, artist, album and artwork. With any other source they show "AudioSync", the source's name and "From your Mac".
- AirPlay speakers no longer jump to full volume when streaming starts or after the AirPlay engine restarts. Each one keeps its own volume and the master slider scales it. After updating, each AirPlay speaker starts at 60% or lower the first time, so set its slider once.
- After the Mac wakes from sleep, AirPlay speakers that were playing come back instead of being switched off as unreachable.
- After an AirPlay engine restart, AirPlay keeps the same latency and volume as before, so your local speakers stay in sync at their saved delay.
- The AirPlay stream no longer starts twice, which could leave a TV showing a file name instead of the track.

### Installing

Download `AudioSync.dmg` and drag the app to Applications. It needs macOS 15 (Sequoia) or later. I don't have a paid Apple developer account, so the app isn't notarized and macOS blocks the first launch: open it once, dismiss the warning, then go to System Settings → Privacy & Security and click Open Anyway next to the message about AudioSync. `SHA256SUMS.txt` has the checksums of every file on this release.

## Windows preview

There's an early Windows 11 build too, for x64 and ARM64 PCs: `AudioSync-0.5.0-windows-x64.zip` and `AudioSync-0.5.0-windows-arm64.zip`. It's an unsigned preview, so SmartScreen warns you the first time you start it (More info → Run anyway). Windows 11 only.

It plays all system audio, or one app, to the PC's own outputs and Bluetooth speakers, each with its own delay, through the same equalizer as the Mac. It also plays to AirPlay speakers through AudioSync's own AirPlay sender (the Mac keeps using its bundled engine), and the PC's own outputs wait for the AirPlay speakers so everything stays in step. An Apple TV that asks for a code gets a PIN prompt: type the code from the TV, and AudioSync remembers the pairing for your Windows user until you choose Forget Pairing.

It looks like a Windows 11 app: Mica title bars, a rounded tray flyout, and speaker rows that line up. If the source can also be heard straight from an output you're listening to, a notice tells you you'll hear it twice, and Show How walks you through the fix and opens the right Settings page.

## Known limits

- From Windows, AirPlay plays only to receivers that take AirPlay 1. Speakers that only do AirPlay 2 and speakers that ask for a password show up with a note and stay off.
- I haven't tried Windows AirPlay with a real speaker yet, and the Apple TV PIN prompt hasn't been tried on a real Apple TV.
- The Windows build doesn't remember its settings between launches yet (AirPlay pairings are the exception).
- On the Mac, everything still runs about two seconds behind, and AirPlay 2 in the bundled OwnTone engine is reverse-engineered, so a HomePod or macOS update can break it until OwnTone catches up.

## Source and licenses

AudioSync's own code is MIT. The Mac app bundles OwnTone 29.2 (GPL-2.0-or-later) as its AirPlay engine, with AudioSync's patches from `setup.sh`, plus the libraries it's built with. This release attaches the patched engine's source (`owntone-29.2-source.tar.xz`), the exact sources of the bundled GPL and LGPL libraries, and `THIRD_PARTY_NOTICES.md`, which lists everything and keeps a written offer for the sources. The Windows zips carry their own `THIRD-PARTY-NOTICES.txt`.
